# 第二轮动态推荐

第二轮只提出当前成功交付版本的可选变化，不写入文稿，也不替代第一轮默认推荐。覆盖文档片段、消息整理、可执行任务说明，以及 Excel 零散资料成表、按原表头追加记录、PPT 补齐两个用户画像头像。共用推荐服务和版本链路；不属于这些目的的操作继续使用原有能力库。

## 与第一轮的衔接

`AgentPlan` 增加可选的 `writingScene`，枚举由 `agent-core/followup-recommendations.ts` 的 `WritingSceneSchema` 提供：

- `document-fragment`：把资料补成文档片段；
- `message`：把资料整理成消息；
- `task-brief`：把截图/反馈整理成可执行任务（包括 AI 任务）。

这是任务目的，不由应用名映射。第一轮未提供此字段时仍兼容；第二轮根据已接受要求、当前内容与真实上下文判断，证据不足返回零条。第一轮推荐仍是 `actions`/`suggestions`；第二轮使用独立 `followupRecommendations`，不改第一轮状态和推荐数组。

第一轮开发可沿用现有 `planTarget` 接口，提供上述可选元数据。第二轮从运行器取得已确认任务目的、用户要求/修改历史、此次执行选用的资料快照、成功提交后的当前片段及固定位置上下文。不另行截图或读取当前前台应用，也不使用此后为其他任务收集的资料。

## 生成与执行

- 单独的只读推荐服务，仅向模型暴露 `present_followup_recommendations`，不暴露编辑工具。
- 单次请求，20 秒推荐超时；非法输出、超时、上下文读取失败均不重试编辑，也不将成功结果改为失败。
- 每条包含 `label`、完整 `instruction`、调整维度 `direction`。最多三条，不凑数量；同维度、同标签去重并过滤不适用场景的维度。
- 文档考虑衔接/组织/重点/精简/解释/语气；消息考虑组织/重点/精简/语气/行动；任务说明考虑范围/组织/验收/限制/待确认/精简。
- 已有验收条件可单列，不声称缺失；待确认内容不能擅自给默认方案；必需项遗漏不能包装成可选优化。语义质量仍依赖模型，结构与范围约束由程序执行。
- 来源与上下文放在 user 数据消息中，不拼进系统规则。超大上下文直接放弃该次推荐；最多传四张图，并声明可用及实际传入数量，不宣称已看过全部素材。

## 生命周期

提交成功即进入 done，完成反馈先显示。宿主上下文回读仍串行留在编辑队列，避免与下一次修改的读取乱序；随后模型推荐独立运行，不占编辑队列。

状态形状为：

```ts
followupRecommendations?: {
  revision: number;
  status: 'loading' | 'ready' | 'unavailable';
  scene: 'document-fragment' | 'message' | 'task-brief' | null;
  options: {label: string; instruction: string; direction: string}[];
}
```

建议绑定目标实例、版本与请求代次。新修改、结束、换目标和关闭会取消旧请求；不响应取消的迟到返回也会被丢弃。成功生成的建议与已提交版本一起保存在当前任务内存中，撤销恢复该版缓存，不再调用模型。若上一版的建议在生成中被中断，撤回后保持无建议，可以自由输入；不伪造固定推荐。没有跨重启恢复承诺。

共享 UI 在输入框上方显示当前版本建议，迟到更新保留编辑节点、焦点、输入法和草稿。空框点击直接发送完整 instruction；有草稿时追加要求并等待用户发送，沿用已确认的交互。加载、失败或零条时保留输入框，不展示伪造的动态按钮。其他目标仍使用原有固定选项。

## 2026-11-07：Excel / PPT 三个新场景

新增 `table-create`（零散资料成表）、`table-append`（按原表头追加）与 `persona-avatars`（补齐两个画像头像）。场景与允许操作集中在 `followup-scope.ts`；第一轮共享的 `writingScene` 可选枚举已兼容六类场景，不要求第一轮必须输出细分标签。

- Excel 仅在首次捕获的选区为空、成功写入矩阵后启用这两个场景。原选区及对应原表头在捕获时冻结，当前值来自已提交版本，不使用“写入几行”之类回执摘要推断。原来已有内容的公式修订保留固定快捷项。
- 新表：统一同义文字、精简说明；存在未使用列时可拆字段。有明确标识且整行相同、同标识无冲突，才开放去重。含对象公式或兼容 `=...` 公式字符串的行不作为相同记录证据；显式 `{text:'=...'}` 仍是文字。去重只清空本范围多余重复行，不移动其他记录。
- 追加：参照原表头与既有记录的写法，精简新增备注；只有现有来源/备注字段和可用来源信息齐备时，允许注明来源。不改原表头、旧记录，不新增行列、不改格式或排序局部列。
- PPT：需要捕获时显式选中两个对象，当前映射仍对应这两个目标，已提交恰好两张图片替换且没有文字改动，原页保留其他对象。仅允许 contain/cover，过滤全部已采用的模式；不推荐焦点裁剪、去背、颜色、尺寸或人物互换。模型仍须根据任务及页面判断是否为画像，不凭“两张图”直接断言。
- PPT 回读后使用最新页面图像替换输入中的旧目标截图，不重复读取来源，也不更换图片身份。
- 模型返回 scene=null 表示不属于新增的 Excel/PPT 场景，恢复原固定快捷项；识别到新场景但零候选则保留空动态结果。前端根据场景与目标类型接收建议，保留自由输入、草稿及版本恢复。

验证：完整后端 228 通过、10 外部环境跳过；桌面 85 通过；TypeScript、构建、UI 生成一致性与 diff 检查通过。首次高并发全套出现旧宿主夹具与输入框测试超时，限制两个 worker 后全套通过，未放宽断言或延长超时。独立只读审查发现公式表达式不能证明记录相同，已先补失败用例后修复，并复核通过。
