# 妥帖 Agent Core v2

## 决策

妥帖采用“确定性任务工作流 + 单 Agent + 可插拔目标适配器 + 受限工具循环”。模型负责推荐与生成修改，程序负责目标定位、状态、校验、写入和撤销。

当前不引入 LangChain 高层 Agent，也不把所有任务强制改成 ReAct。目标适配器声明执行策略：边界明确的 Word／Excel／PowerPoint 实时操作使用 `single-pass`；需要观察中间结果的矢量、场景或复杂布局使用 `bounded-react`。Blender 保留 MCP 与真实 `look` 验证。

`single-pass` 现在是实际执行约束：每次只接受一个完整候选，校验成功即结束模型循环；校验失败允许在预算内修正，同时提交多个工具调用会被拒绝。Figma 的有界循环已接入实际候选 PNG 观察和独立 review 工具，适配器强制检查最新候选后才能提交；`requiresVisualVerification` 字段本身不是验收证明，Illustrator 尚未接入该闭环。Blender 的修改后看图仍由原有专用循环执行。

任务状态已经收敛为确定性 `TaskWorkflow`。暂不增加 LangGraph 运行依赖：先让状态和运行上下文成为清楚、可测试、可序列化的领域数据；出现跨进程恢复、后台长任务或多个暂停点时，可将同一状态图迁移到 LangGraph，而不改变目标适配器。

## 当前边界

- `src/agent-core/model-gateway.ts`：唯一模型供应商边界，继续兼容方舟 Agent Plan 与 OpenAI 风格接口。
- `src/agent-core/context-builder.ts`：把内容包记录、二进制图片、视频观察与目标视觉上下文组装成模型输入。
- `src/agent-core/tool-loop.ts`：供应商无关、有最大轮数、只调用目标白名单工具的执行循环。
- `src/agent-core/execution-policy.ts`：旧目标的默认执行策略；新目标优先在适配器上声明策略。
- `src/agent-core/task-workflow.ts`：产品任务状态与合法转换，模型不能创造状态。
- `src/agent-client.ts`：保持兼容外观，负责提示词与 Blender 特殊视觉循环，逐步缩减为规划／执行服务组合。
- `src/file-runner.ts`：保留现有运行入口，改为组合核心模块，不再自行拼装模型输入或维护无约束状态字符串。
- `src/targets/editable-target.ts`：目标适配器协议；宿主写入仍由 Office.js、Figma 插件、Blender MCP 等真实接口负责。

## 不变量

1. 用户于 11 月 3 日确认：Office 目标在快捷键捕获时固定，发送前后均不跟随光标或前台软件变化。未结束任务拒绝重复捕获或切换目标；位置说明来自已捕获上下文。结束任务后才能建立新目标。
2. 模型只看到当前目标实际支持的工具。
3. 模型可以准备修改，但不能直接归档内容包、提交事务或撤销。
4. 每个工具循环有轮数上限，取消信号在每次工具调用前检查。
5. 来源内容与目标文档中的指令只作为资料，不获得系统权限。
6. 写入必须由目标适配器校验版本和范围；结果不确定时禁止自动重试。

## Word 样板（2026-11-02 已切换并实机验证）

### 结构化 Patch

`word-patch.ts` 是纯数据到 Word OOXML 的编译边界。`paragraph` 与 `image` 构成有序块，文字 runs 支持加粗、斜体、下划线、字号、颜色，段落支持对齐；图片仅解析本轮选择的内容包 PNG/JPEG，保持比例。模型不能提交 OOXML／HTML／代码／路径／任意 URL。

图文块和段落格式仅在段首／空行开放，宿主在写入前重新检查真实范围起点，防止段落属性影响已有半段文字；纯文字插入仍支持段落中间。编译结果保留末尾空段落，防止 Word 消费末段标记后将原有后续段落接到图片右侧。

11 月 3 日实机补强：纯文字工具支持 `layout: paragraph | inline`，段首默认编译为独立段落，句中默认行内，明确需要连续文字时可显式 inline。模型只输出新增片段，不能把正文上下文重新插入；包含插入点前后完整原文的候选会被拒绝并返回修正信息。任务结束清空草稿与宿主锚点，防止旧要求漏入新任务。

```mermaid
flowchart LR
  UI[浮窗与快捷键] --> W[确定性任务工作流]
  W --> C[正文／位置／内容包／当前版本]
  C --> M[模型网关与规划]
  M --> T[单次候选或有界工具循环]
  T --> P[Word Patch 校验与编译]
  P --> H[Office.js 版本检查／范围写入／回读]
  H --> R[已提交版本与撤销]
  R --> W
```

### 版本事务

- `WordLiveTarget` 保留已提交版本和独立候选。`begin` 不再撤回旧版本；生成失败／终止丢弃候选，旧版本及其撤销能力仍在。上下文增加当前插入内容，继续调整提供完整替代版本。
- Word 宿主保存真实 Range 与每版回读 OOXML。写入前核对完整正文版本和妥帖自有范围；更新用一次范围 Replace，避免先删后生成。撤销 V2→V1 使用上一版回读内容，V1→V0 删除自有范围，不恢复整个文档而覆盖其他编辑。
- 任务层消费可选的 `revision` / `mutationUncertain` 能力，保存对应结果与对话。撤销至 V1 保留完成页、继续调整与资料；撤销至 V0 回收集流程。失败保留上一版时显示失败原因。
- 已进入宿主写入但回执丢失／Office 报错时冻结目标，明确结果不确定；只有宿主明确说明尚未开始写入，才保留可继续使用的旧版状态。不自动重试或声称失败必然未写入。Office.js 不提供这条链路的通用 ACID 事务保证。
- 每个任务最多 20 版，单次 10 万字符、8 张图片／总计 12 MB。历史仍在内存中，结束任务／关闭加载项／重启服务后不能恢复撤销链。

宿主协议增加版本号，旧加载项会提示重新打开，避免富文本被旧接口默默当作纯文本插入。传输仍复用 OfficeBridge，不增加独立服务或框架依赖。

本次通过 142 项后端检查（10 跳过）、56 项桌面检查及 TypeScript 编译。用户授权结束旧任务、保留文稿结果并切换新版后，使用独立合成稿与隔离资料完成真实 Word 图文插入、替换、回读和逐级撤销；真实模型连续两轮将蓝色加粗标题由 16 磅改到 18 磅并保留图片，逐级撤销恢复原正文及格式。正常运行服务已恢复。Word 可能重建内部绘图标识，不承诺文件字节完全相同。本轮未重测全局快捷键及 Word 原生 ⌘Z。证据见 [验证记录](evidence/word-v2-verified-2026-11-02.json)。

### 后续平台扩展

Word 当前只编辑本任务创建的区域，不支持任意原文格式修改、表格、浮动图片或全篇重排。已在独立 Word 测试稿验收段落边界、图文排版、连续调整及逐级撤销。PowerPoint 已于 11 月 3 日迁移：`prepare_powerpoint_edit` 接受当前选中对象的图片映射与单段文字，候选／成功版本分开，宿主跟踪图片 ID 变化、文字字体和逐级撤销；本任务的图片几何随修订链保留。中文需先显式固定字体，复杂富文本／多段／动画／任意新对象暂不支持。Excel 与 Figma 同日补齐多版本事务、明确写入前拒绝与未知写入的区别；Excel 区分公式／纯文字并检查复杂区域，Figma 增加临时画框真实渲染和模型检查。详见 [两端工作流与边界](excel-figma-workflow.md)。

图文候选在程序／Python 中编译，模型不提交代码或任意路径。PPT 多对象写入仍包含多个 Office 调用，失败时不能保证自动回滚；只有宿主明确 `mutationStarted=false` 才可继续使用上一版，其他情况冻结。版本历史上限 20，仍不跨服务或加载项重启恢复。最新实机与自动检查范围见 [验收矩阵](office-workflow-checklist.md)。

### 可持久化运行上下文

将目标快照 ID、来源 ID、用户要求、能力、模型／提示词版本、工具结果和修订 ID 保存为不含宿主对象的 `RunContext`。完成后再评估使用 LangGraph checkpointer 接管跨重启恢复。

### 连接恢复与任务收尾（11 月 3 日验收修复）

Word、PPT、Excel 与 Figma 共用 `office-live/bridge-client.js`，各宿主只提供读取身份与执行固定命令。客户端串行保留未完成批次和待确认结果；结果响应丢失时只补发回执，不重放编辑。临时断网保留会话，凭据更新不重建适配器；服务明确返回旧会话失效后丢弃旧批次，超期命令在触碰文稿前拒绝。Figma 的外层 relay 仅在没有待处理宿主操作时重试初始失败的页面。

原生宿主检查本机服务健康，单次启动与退避避免重复进程，日志句柄复用。状态快照带运行标识，后端重启会结束旧弹窗／撤销展示并明确告知，不能冒充持久化恢复。原生等待回调携带递增代次，控制操作确认完成后作废旧观察者，避免快速停止再发送时旧回调结束新任务。

实时任务撤至 V0 后先进入 idle，由任务所有者释放锚点；不再为即将释放的锚点自动规划。界面把正在运行／等待控制回执与已确认的未知写入区分开：正常写入继续显示加工，失败且结果未知才展示只读提示。自动推荐缺失时最多向模型纠正一次，不用标题或固定文案伪造建议，不增加常规成功调用次数。最新逐平台实机范围见 [完整交互验收](four-platform-interaction-checklist.md)。
