## 2026-10-28 当前桌面入口

Swift / WKWebView → 同一 HTML 组件库 → 47721 本地 HTTP → `DesktopAgent`。协调器选定一个目标，拒绝旧目标卡片启动错误任务：

- `SceneRunner` → `AgentClient.plan/execute` → Blender MCP → 独立场景事务。
- `FileRunner` → `AgentClient.planTarget/executeTarget` → `OfficeFile` → `office/files.py` 的原生对象操作 → 独立 DOCX/XLSX/PPTX 文件副本。
- 系统剪贴板 / 留在妥帖只存放来源，不触发模型执行。

文件计划与执行只暴露目标格式真实支持的工具。模型读取已有内容/尺寸/公式等事实后自行组合操作，没有按“苹果 / 研究笔记”等来源类别写推荐分支。推荐不直接执行，点击选中方向后才执行副本工具，用户应用后才替换原文件；指纹保护和字节备份用于冲突检查与撤回。文件上下文只来自已保存内容，不能代表原生 app 实时选区。

以下保留早期 Electron / Blender 的技术说明：

## 早期结构

- `AgentController` 管理参考、真实场景上下文、对话历史、模型计划、预览、确认和撤回。
- `AgentClient.plan` 接收用户自然语言、参考图、真实视口、对象清单、鼠标射线信息和本地资产目录，返回可修改的操作计划与必要澄清，不使用固定意图枚举。
- 用户确认计划后，`AgentClient.execute` 通过模型真实 function/tool calling 组合 MCP 工具。工具参数从已连接 MCP server 的 `tools/list` 读取；当前接通场景查询、真实视图和通用 bpy 执行。
- `agent_scene` 为原场景的对象、几何和材质创建独立副本。模型操作限制在副本内；用户看到实际变化后才提交。
- 文件、网络、系统操作和原场景的越界访问不通过预览工具直接开放。这是工具权限边界，不是把自然语言任务限制为某个动作。付费外部生成服务仍未配置，不能宣称已经可用。

## 场景与落点

`spatial.py` 读取对象、父子关系、世界包围盒、材质、选择和单位。鼠标坐标通过视图矩阵反投影形成世界射线，读取实际命中对象、表面点和法线；没有表面命中或从非视口区域拖入时，明确标为位置未确定，交由对话澄清。

对已知篮子可补充篮底几何、射线在篮底平面的投影和与篮子的关系。这些是给模型的事实，不会自动把所有任务改成“放入篮子”。已有苹果也是实际对象清单的一部分。模型应结合数量、位置和用户要求，区别“再添加一个”“移动已有的”“放在篮外”等请求。

## 验证进度

- 通用场景事务已完成一次真实 Blender 测试：只在副本中修改桌面材质并添加立方体、正式场景校验不变、提交幂等、撤回。系统访问代码被拒绝。
- 12 项 AgentController 单元测试通过，覆盖自然语言复合请求、上下文传递、澄清、API 失败、场景变化、取消、非 AI 模式不读剪贴板与不确定提交状态查询。
- 自然语言真实 API 已生成“桌面浅蓝＋篮外绿色立方体，保留篮子苹果”的复合计划；真实多轮工具执行已通过：查询实际对象名后修改材质并创建 GreenCube，调用 look 看图核查；差异为新增 GreenCube、修改 Table，原场景未改变。预览图与记录在 docs/evidence/compound-preview.png 和 compound-agent-result.json。
- 新版拖放、推荐、预览与应用已由用户实际操作通过，主要反馈为等待时间长；用户输入复合自然语言和连续多轮调整仍需专项 UI 验收，不能用开发者 API 检查代替。

模型、资产和场景能力可继续通过工具层扩展。当前真实场景执行仍只接通 Blender，并不等于已实现任意应用的通用桌面 Agent。浏览器复制另有本地剪贴板：记录落在 `.local/clipboard/`，可贴到系统剪贴板、留在妥帖或 Blender。Blender 已支持文字和图片；Office 文件目标接入见本文顶部。
