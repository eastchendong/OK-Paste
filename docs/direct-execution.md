# DeepSeek 快速执行（2026-11-07）

## 当前已实现

Word、普通输入框 input-live、Excel、PowerPoint 的实时执行，在配置了既有 DeepSeek 推荐 Key 时，直接调用 `deepseek-flash`，关闭 thinking，正常成功路径只请求一次候选。自定义要求、多个来源和后续调整都不再单独请求旧模型制定计划。不增加框架或第三方依赖。

执行链：读取固定目标 → 组织真实来源与用户要求 → DeepSeek 返回一个准备工具调用或必要追问 → 原目标适配器校验候选 → 原宿主校验版本并写入 → 保存修订与撤销 → 后台请求后续建议。

- `src/agent-core/deepseek-gateway.ts`：唯一新增模型连接，复用本机 `.local/recommendations-config.json` 的 Key；不复用旧供应商 Key，不记录 Key、正文或图片。
- `src/agent-core/direct-executor.ts`：按真实目标选择准备工具，用户/来源/目标数据放在 user 消息中，system 只保存稳定规则。允许一个 `request_clarification`；补充答案会连同原始要求和问题传入下一轮。
- `src/file-runner.ts`：选择快速执行策略；完成候选后省掉一次重复的完整目标读取。原宿主提交仍核对 expected revision 和原内容；PPT 的 commit 内部读取与校验继续保留。
- `src/agent-core/followup-recommendations.ts`：后续只读建议也使用同一 DeepSeek 连接，仍在成功写入后独立运行，不阻塞修改结果。

Figma、Blender、Illustrator 以及已保存文件目标的实际编辑保持原有执行流程；Figma 的真实渲染与视觉检查没有取消。本轮没有实现 PPT 参数调整的零模型请求路径；图片模式调整仍通过同一单次候选路径执行。

## 失败与范围

- 准备候选的结构或适配器校验失败，最多修正一次；不增加无限循环。
- 网络、超时、401、429、模型输出截断直接失败，不偷偷调用旧模型补生成。
- 校验阶段只调用白名单 prepare 工具，绝不提交宿主写入。真正 commit 不在候选重试循环内。
- 模型响应后、准备后、提交前继续检查取消；写入结果不确定仍冻结，不自动重发。
- 固定目标、只编辑本任务范围、手工修改保护、V2→V1→V0 撤销及每任务版本上限保持原有机制。
- PPT 整页只读捕获仍禁止执行；普通输入框的物理粘贴能力没有因换模型变成已实机通过。
- 事实主体、时间和限定必须保留；已有表头及常规字段映射不要求用户重复确认。提示约束不能替代语义质量评测。

## 配置与回退

无需再输入 Key：已有独立推荐配置时自动使用快速执行。没有 Key 的历史安装继续旧路径。若要明确回到旧执行和后续建议，可在运行目录 `.local/execution-config.json` 写入 `{"enabled":false}`；删除该文件或改成 true 恢复 DeepSeek。这个开关不改变首轮推荐。

执行请求上限为 30 秒；PPT 输出预算 2048 token，其他三类 8192 token。后续建议 20 秒/2048 token。输出预算耗尽不提交半截候选，而是明确提示缩小范围。

## 观测与检查

- `.local/deepseek-events.ndjson`：stage、模型、请求耗时、usage、结束原因及工具名，不含正文/图片/Key。
- `.local/execution-events.ndjson` 和状态 `executionMetrics`：目标读取、输入组装、模型、候选准备、宿主提交和总耗时、请求数。总耗时从执行队列开始到提交完成，不是物理快捷键端到端延迟，也不包含后台后续推荐。
- `tests/direct-executor.test.ts`、`tests/direct-workflow.test.ts`：候选、四类接线、无重复规划、追问连续性、停止、失败保留旧版、宿主未知写入、逐级撤销及只读范围。
- `node --import tsx scripts/check-direct-execution.ts`：只使用虚构资料请求真实模型，不调用 Office、原生输入或系统剪贴板。

最终完整后端回归 268 通过、10 外部环境跳过（排除会改变系统剪贴板的 clipboard.test.ts）；共享桌面检查 90 通过；TypeScript、构建、UI 生成一致性和 diff 检查通过。本机端口相关测试需允许 loopback，受限沙箱首次运行出现 EPERM，开放本机测试端口后完整通过；未放宽断言。

## 真实模型小样本结果

四场景各三次，最终 12/12 生成通过结构和本次候选校验的结果，每次恰好一个模型请求：0.744–1.284 秒，中位数 0.896 秒，P80 1.098 秒。输入是短小的虚构资料；PPT 使用明确姓名标签，不含真实图片。计时仅包含请求和内存候选校验，不含目标捕获、完整文稿读写、PPT Python 处理、实际图片识别或原生界面。重复样例可能命中缓存，不能据此承诺实际端到端 1 秒或给出与旧日志的严格加速倍数。

首轮结构 12/12，但人工阅读发现一次把引导岗携带要求扩大到所有人；第二轮 11/12 交付候选，Excel 曾对已有表头做多余追问。分别收紧事实归属和澄清阈值后完成最终轮；前两轮原始记录保存在忽略目录 `.local/direct-execution-smoke-baseline.json`、`.local/direct-execution-smoke-round2.json`，不覆盖失败证据。最终样本没有复现这两个问题，不代表任意资料语义质量已保证。

本轮不以自动回归或模型候选测速代替真实原生宿主写入验收。部署前只允许空闲、无可撤销版本和无不确定写入的服务切换，保留更新前文件备份；不结束用户文稿任务、不归档或清理用户资料。
