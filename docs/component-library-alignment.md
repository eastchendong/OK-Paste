## 同日后续：紧凑选区操作条

用户明确要求减小高度和显眼程度，组件源选区操作条现为 32 点高、11 点常规字重、14 点图标；原生固定宽 214 点，按钮高 24。生成资源已同步。原生与网页均优先放在整个选区下方，留 6 点间距；下方放不下才翻转，边缘约束与多显示器保留。原生 9 项位置检查、网页 12 项检查和桌面 21 项检查通过；独立 AppKit 渲染检查文字未溢出。当前对浏览器／原生工具条尺寸的最新规范以此节为准。实际前台跨 App 弹出位置尚未由本轮自动化确认。

## 同日后续：用户要求的来源同行布局

用户明确指定来源链接必须在「文字／图片」类型右边，不得换行。已相应更新唯一源文件的 `.source-meta`、来源文本收缩及图标规则；长名称省略显示，点击地址保留。此项是用户对组件规范的后续修改，优先于本文早前保持远端原文件不变的描述。只同步界面运行资源，不重签宿主。

用户点击头像前后的截图进一步暴露原生激活外观差异。桌面已改为原生 NSVisualEffectView popover，固定 behindWindow、active、aqua 和非 emphasized；保留 30% 覆盖，替代这里的 NSGlassEffectView 自适应玻璃。此前 clear Liquid Glass 的记录为更早实现。高度不变但点击后变色，不能仅以卡片尺寸或背景解释。

新增 `npm run test:native-glass`，覆盖 3 尺寸、2 父级外观、4 激活通知和重新挂载；与 21 项共享组件检查及原生构建通过。记录见 [原生材质状态检查](evidence/native-glass-focus-2026-10-29.json)。测试不等价于桌面像素比较。

## 同日后续：桌面原生玻璃的薄覆盖

用户明确要求改善偏白后，桌面端在原生玻璃上统一使用 30% 白色薄层，推荐悬停为 36%，移除 CSS 模拟反光。材质登记和覆盖样式共用一个选择器集合，避免动态等待／错误／结果漏用新样式；普通透明容器不加入。以下早前 70% 覆盖的记录为调整前状态。官方浏览器组件 HTML 保持不变，独立原生划词条本轮没有修改。

21 项共享检查通过。用实际 WKWebView 在相同条纹背景渲染最小控件对照，确认三类控件相同位置像素一致、白色覆盖从 70% 降到 30%。[记录](evidence/glass-coating-2026-10-29.json)、[调整前](evidence/glass-coating-before-2026-10-29.png)、[调整后](evidence/glass-coating-after-2026-10-29.png)。这组图验证网页覆盖层，不代表原生玻璃在真实桌面上的完整合成。运行目录已同步并重启同一宿主，实际辅助功能 true；没有重签或变更全局显示设置。

## 单一设计来源

同日全面核查：补齐桌面 `#toast` 和原生 `SelectionToolbarView` 的玻璃背景。主浮窗与划词工具条共用 `NativeGlass.swift`，macOS 26 使用 clear 且无额外 tint，旧系统回退到 behindWindow popover。划词工具条保留官方 white-a11（90%）表面，内容包／方向保留 white-a9（70%），不强行把官方不同透明度改成相同颜色。结果卡片原先同时匹配 completion-header 和 office-result，上报改为单次 DOM 查询，避免重复背景；不可见祖先的背景不再残留。所有 demo-glass 一并禁用 WebKit 二次模糊。

原生材质范围已检查：内容包、推荐按钮／等待与错误条、方向输入、工作输入、完成反馈／文字与 Office 结果、继续调整菜单与输入、引用菜单、选区操作条、详情／归档、返回／折叠菜单、拖放确认、提示消息。任务外层容器在工作和完成阶段为透明，不额外铺背景；设置使用原生普通窗口与实色控件；浏览器扩展在网页内使用 CSS 玻璃，不由妥帖跨进程铺原生背景。共享组件 21 项检查通过，真实 AppKit 工具条层级与离屏渲染检查通过；离屏图片不能证明背后桌面的模糊质量。

同日材质修复：桌面原生玻璃使用 clear 样式且不额外叠加白色 tint，由官方 HTML 统一提供表面底色。推荐等待状态 `.direction-status` 与推荐按钮、输入框、内容包共同上报原生材质区域。用户授权后已关闭系统「降低透明度」，这与组件文件版本是否更新无关。半透明表面会受真实背景颜色影响。

`scripts/sync-component-library.mjs` 读取官方 HTML，生成网页选区操作条的原始样式、图标和中文文案，以及原生窗口使用的颜色、字体和图标资源。生成文件带来源指纹；内容未变时不重复写入，避免构建过程中修改输入文件。前端构建、桌面构建与运行目录同步都会先执行该脚本。

桌面产品继续加载同一份官方 HTML。`desktop-overlay.js` 为实际控件添加组件目录中的对应类，保留真实状态、事件、数据及 AppKit 鼠标穿透和玻璃背景。

## 已完成的检查及边界

- 68 项逻辑测试通过，10 项依赖可选 Office 环境的测试明确跳过。
- 17 项共享桌面组件检查通过；前端类型检查、构建和 Swift 桌面构建通过。
- 归档改用标准素材预览时曾丢失图片替代文字，既有检查发现后已修复并重跑通过。
- 本机安装版与 Application Support 运行目录已更新，旧 Electron 没有启动。没有重置场景、提交目标文件、发送消息或更换模型密钥。
- 重建使用本机 ad-hoc 签名；最终设置窗口显示辅助功能未开启。原生跨应用选区的前台验收需要有效授权，离屏图仅证明组件自身外观。
- 标准源库没有专门的系统文件选择器或系统权限界面，继续使用 macOS 原生界面。样式对齐不扩大这些界面的业务能力。
- 以上修改为本机未提交内容，未向 GitHub 推送。另一个进行中的图片扩展工作保留，只补齐提示条样式并重建其已有加载目录。

## 更新方式

在 `prototype/` 执行 `pnpm build` 或 `node scripts/prepare-desktop-runtime.mjs` 会同步生成资源。Swift 控件有变化时，在 `prototype/desktop-preview/` 执行 `zsh build.sh` 并重启 `~/Applications/妥帖.app`。只改 HTML／网页脚本时优先同步运行目录，避免无必要地重签原生宿主。
