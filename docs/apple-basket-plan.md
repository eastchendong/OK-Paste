# 网页苹果 → Blender 篮子：当前验证范围

根据用户 2026-10-25 提供的方案记录。此文档是开发计划，不表示完整原型已实现。

## 最新产品方向（2026-10-25）

用户进一步明确：苹果、篮内/篮外、已有苹果只是示例。妥帖需要自然语言意图识别与可组合的 Agent 工具执行，不能限制为预设动作。当前实现已转为可对话的 Blender Agent；以下固定用例作为历史验收参考，而非产品能力边界。当前结构与状态见 [agent-architecture.md](agent-architecture.md) 和 [development-status.md](development-status.md)。

**阅读提示：** 下文“下一阶段”“当前准备”“尚待开发”等保留早期方案原貌，不代表最新开发状态；“模型仅推荐、不可生成代码”等旧边界也已由通用 Agent 方案更新。已实现内容以开发状态和技术交接为准，保留本文是为了追溯需求演变。

## 交互校正（2026-10-25，当前优先）

用户已明确：不占用 `Ctrl/Cmd+V`。进入 AI 模式并收集图片后，通过拖放苹果图片到 Blender 窗口激发意图对话框；无需精确命中篮子几何。能识别落点则使用落点，否则结合当前选中对象与固定测试场景的篮子，并在确认框中标明绑定依据。确认意图后通过 MCP 生成临时预览，最终确认后才加入正式场景。

以下早期工作包中的“选中并按快捷键绑定”等描述以此交互校正为准。

## 下一阶段开发计划（2026-10-25 确认）

下一阶段目标：交付一个可在 MacBook 上操作的最小原型，完成「快捷键进入模式 → 复制网页苹果图 → 切到 Blender 并绑定篮子 → 推荐意图 → 临时预览 → 确认加入 → 撤回」。复用已下载的苹果模型，不调用三维生成服务。先验证一个固定篮子场景，不追求任意场景或精确跨窗口拖放。

### 技术栈与语言分工

| 层 | 选型 | 负责内容 |
| --- | --- | --- |
| App 桌面壳 | Electron + TypeScript | 全局快捷键、剪贴板采集、任务编排、窗口管理、API 请求、MCP 进程生命周期 |
| App 界面 | React + TypeScript + Vite，普通 CSS | AI 模式指示、苹果缩略图、意图卡、预览、确认/取消、大小和高度调整、撤回 |
| 进程通信 | Electron preload + contextBridge + 类型化 IPC | 界面只调用明确的任务操作；API Key、文件和 MCP 调用留在主进程 |
| MCP 客户端 | 官方 MCP TypeScript SDK，stdio transport | 在 Electron 主进程启动并连接 MCP 服务，发现并调用工具；不是让模型 API 直接连接本机 |
| Blender 接入 | 现成 mcp-for-blender：Python MCP server + 配套 Blender 插件 | 场景数据、视口截图、执行 Blender 操作；允许此层使用 Python，不另建 Python App 后端 |
| 场景操作 | 参数化 Blender Python / bpy，经 MCP 执行 | 读目标、导入 GLB、建立预览场景、尺寸适配、提交、取消、撤回 |
| 视觉推理 | 沿用仓库火山方舟视觉 API 配置 | 分析参考图、场景截图与对象信息，返回意图和有限的调整建议；不生成三维模型 |
| 数据与状态 | TypeScript 状态机 + Zod 校验 | 校验目标对象、任务版本、模型输出和执行参数；防止重复提交和过期结果 |
| 存储 | 本地素材 + 任务 JSON/操作记录 | 固定模型和素材清单复用现有 assets；首版无需数据库或单独 Web 服务 |
| 开发验证 | pnpm、tsx、Vitest；手动 Blender 集成验收 | TS 接入探针、状态测试和真实 Blender 场景验证；现有 Python 验证脚本可保留 |

不新增三维生成服务、自研复杂 Blender 插件、独立 Python 业务后端或通用 Agent 框架。依赖版本在首次连接成功后锁定到 lockfile 和运行说明，记录 macOS、Blender、MCP server/addon、Electron、Node 和模型配置。

### 模块分工与连接方式

1. `capture`：在 AI 模式中读取本次新复制的图片，生成来源记录和缩略图。仅复制图片时不能保证有网页 URL；来源缺失要如实显示，后续 Extension 补充标题、页面 URL 和图片 URL。
2. `blender-client`：封装 MCP 连接、工具发现、超时、图片返回值归一化。实际调用以安装版本的 `tools/list` 为准，不在界面中写死上游工具名称。
3. `vision-client`：沿用 `ARK_BASE_URL`、`ARK_MODEL` 和本机密钥配置，使用 TS HTTP 客户端发请求，校验最终响应；不假设服务商支持未经验证的 JSON Schema 参数。
4. `placement`：把选中对象的场景数据转换为确定性初始放置参数；模型只返回允许的意图或调整，不直接执行模型生成的任意代码。
5. `preview`：在独立临时场景中展示苹果与原布局，沿用视角；正式场景在确认前不增加苹果对象。临时场景本身会产生临时数据，不声称 Blender 会话完全未变。
6. `task-controller`：管理采集、目标、预览和操作记录；统一处理确认、取消、失败和撤回。

通信链为：React 界面 → preload/IPC → Electron 主进程 → 一路请求视觉 API，另一路通过 MCP SDK/stdio → Python MCP server → Blender 插件 → bpy。截图和对象信息经同一路返回。无需额外 FastAPI、Express 或远程 MCP 托管。

来源记录保存 `taskId`、图片本地引用、采集时间、可获得的来源信息。目标记录保存 Blender 实例、场景和目标对象身份、世界空间包围盒/变换及绑定时快照。预览记录保存本次新增对象、根节点、变换和预览版本。操作记录保存 `operationId`、确认的预览版本、提交结果和撤回状态。对象名称用于显示，不单独作为长期唯一标识；测试场景可配置稳定标识。

### 按顺序完成的工作包

| 工作包 | 具体开发工作 | 退出条件 |
| --- | --- | --- |
| 0. 接入探针 | 用 TS 脚本连接现有 MCP，列工具，读取选中对象和场景，获取一张 Blender 截图；复用现有图片 API 验证 | 真实截图可显示、对象及尺寸可读；记录版本和调用方式；API 返回有效视觉结果才标为已通过 |
| 1. 场景闭环 | 准备固定篮子场景，用本地 GLB 做导入、尺寸归一化、临时预览、提交及撤回 | 不依赖网页或模型猜测，能把固定苹果放入候选位置；取消不改变正式场景；提交一次后可撤回 |
| 2. App 骨架 | Electron/React/TS、全局快捷键、AI 模式、复制图片缩略图、目标绑定按钮、状态提示 | 能从浏览器采集图片，切换 Blender 后绑定篮子；弹出 App 后仍持有原目标 |
| 3. 视觉理解 | 把来源图片、绑定时视口截图、候选对象及几何摘要一起发给 API；生成意图卡；预览后做一次视觉检查 | 模型识别苹果参考和篮子目标；无法确定时提示选择；无效输出不执行 |
| 4. 演示闭环 | 接通确认/取消/撤回、放大缩小和升降、错误处理、运行文档和真实流程录屏 | 完整跑通验收用例；没有隐藏的手动导入或假成功状态 |

工作包 0 是第一项，不先投入完整 UI 美化。遇到 MCP 不能返回图片或场景字段，先补适配/通过其代码执行能力读取必要字段；只有现有入口确实无法覆盖时，才新增少量插件逻辑。最小版本采用选中篮子后按快捷键绑定目标，鼠标侧键先映射同一快捷键。

### 放置算法与截图检查

首版使用世界空间数据，考虑篮子/模型的父级变换和导入 GLB 的多个节点。苹果以统一根节点控制，按篮子尺寸给出保守的初始大小，模型底面而非原点对齐候选承托高度。

优先使用测试场景明确的内部放置锚点；若用包围盒中心加高度偏移，需在运行说明中标明它是启发式候选位置。外包围盒不能证明篮内空腔或无碰撞，截图也不能恢复精确深度。首版允许通过按钮微调高度与大小，不宣称物理放置正确。

视觉模型检查预览中的大小、明显悬空和穿插，最多建议一轮调整。调整建议转换为有上下限的缩放/高度参数，再由 bpy 执行。用户修改预览参数后更新预览版本；最终确认提交已看到的那批对象，不重新导入或重新估计位置。

首版优先用 MCP 提供的视口/渲染图，减少对系统截屏的依赖。若无法可靠捕获临时场景，先验证固定视角离屏预览，再接侧栏图片；不能把正式场景先改掉再截图称为确认前预览。

### 状态、失败和回退

主要状态：待机 → 收集参考 → 已绑定目标 → 分析 → 意图待选 → 预览准备 → 预览待确认 → 提交 → 完成；完成后可撤回，提交前可取消。

- MCP 未连接、目标未选中、素材路径不存在：停在当前步骤，给出具体修复提示。
- 来源更换、目标删除/移动或场景切换：旧预览失效，重新绑定或刷新；切换前台应用本身不改变目标。
- API 超时/无效输出：保留内容包，支持用户主动重试，不把无效结果视为成功。
- MCP 写入超时：先查询本次 operationId 对应对象，确认实际状态后再决定重试；重复点击不导入两份苹果。
- 取消：清理本任务临时场景及独占的临时资源，不删除共享的篮子、材质或用户对象。
- 撤回：只处理本次提交的对象；如用户后续编辑这些对象，先报告冲突，不默默删除修改后的成果。不用连续发送 Cmd+Z 代替操作记录。

### Mac 权限与首版范围

全局快捷键用 Electron，侧键映射由鼠标设置完成；首版不自行开发全局鼠标监听。复制图片模式不需要框选遮罩。Blender 内部返回图像不等同于操作系统屏幕录制；如果后续增加桌面截图，再申请屏幕捕获授权。

窗口元信息可以后续用 `get-windows` 的 TS 接口补充，先验证 Electron 打包及其原生二进制依赖；其窗口标题/URL读取可能要求额外系统权限。不把“获取所有窗口”作为首个 Blender 闭环的前置条件，也不把窗口列表当作场景语义。

首版只使用普通组合键，不默认要求辅助功能控制、完全磁盘访问或 AppleScript 自动化权限。实际使用某项系统能力时检查对应权限；权限拒绝要有可见提示。应用从后台触发时不抢走来源窗口焦点，获取来源/目标后再显示可交互面板。

## 验收任务

从网页收集一张苹果图片，在 Blender 中指定篮子，结合视口截图和 MCP 场景信息推荐放置意图，将预下载的固定苹果模型放入候选位置，预览大小与位置，由用户确认后加入正式场景，并可撤回。

图片只用于识别意图；不同苹果照片映射到同一模型。不验证图片生成三维、任意场景理解、精确跨窗口拖放、物理碰撞。不另写复杂 Blender 插件，优先复用现成 Blender MCP。

## 流程约束

1. 在 Chrome 复制苹果图片，保存来源信息，展示已收集参考的缩略图。快捷键优先，截图采集与鼠标侧键后续补充。
2. 切到 Blender 绑定目标，首版允许先选中篮子。获取视口截图及对象身份、位置、尺寸、旋转、层级和选中状态。目标不明确时要求点选。
3. 推荐“根据这张参考图，将苹果模型放入当前篮子”。意图和截图检查使用火山方舟 GLM-5.3-Flash。
4. 参数化操作导入固定 GLB、统一根节点、读取包围盒，计算初始缩放和候选位置。篮子外包围盒不等于内部空间，必要时在演示场景配置内部锚点，并如实说明。
5. 在临时预览场景导入，沿用正式场景的视角与布局，检查大小、悬空、穿插和旋转。最多自动调整一轮；保留放大、缩小、上移、下移和取消入口。
6. 确认后提交同一批对象和已预览的变换，记录本次新增对象。取消清理预览；撤回只删除本次加入的对象。
